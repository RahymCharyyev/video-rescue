# Video Rescue

Десктоп-приложение (macOS, Windows) для восстановления видеозаписей, оборванных разряженной батареей, вынутой картой или зависанием камеры.

- **Sony .RSV**: заголовок не записан, данные целы. Приложение само находит, где начинаются кадры.
- **MP4 / MOV без индекса (moov)**: обычная оборванная запись с любой камеры, которую поддерживает untrunc (Sony, Canon, Panasonic, GoPro, DJI, телефоны…).
- Нужен **эталон**: целый ролик с той же камеры с теми же настройками. Приложение само ищет его в той же папке и подсказывает лучший вариант (соседний номер клипа, тот же тип файла, у Sony есть дорожка rtmd и XML-метаданные).

## Два режима

| | Новый файл | Починить на месте |
|---|---|---|
| Исходник | не трогается | дописываются заголовок и индекс |
| Место на диске | размер видео (20 ГБ клип → 20 ГБ) | несколько МБ |
| Откат | не нужен | кнопка «Отменить починку», байт в байт |
| `-s` (пропуск мусора) | можно | нельзя |

В режиме «на месте» приложение:
1. запускает untrunc с `UNTRUNC_MOOV_ONLY=1`: он строит индекс и **не копирует** гигабайты данных;
2. сохраняет байты, которые будут перезаписаны, в `<файл>.videorescue-backup.json`;
3. дописывает индекс в конец файла и пишет корректный заголовок (`ftyp` и пр. из эталона плюс `mdat`) на место мусора;
4. переименовывает `.RSV` → `.MP4`, если включена эта опция.

Сами кадры и звук не меняются. Смещения в индексе указывают прямо на данные в исходном файле.

## Структура

```
src/engine/     движок без Electron: разбор MP4, определение поломки, подбор эталона,
                запуск untrunc, починка на месте и откат (можно использовать из CLI/Node)
src/main/       Electron main process + IPC
src/preload/    contextBridge API (sandbox, contextIsolation)
src/renderer/   React UI (на русском)
patches/        патч untrunc: режим «только moov»
scripts/        сборка untrunc + ffmpeg из исходников (только GitHub, без ffmpeg.org)
test/e2e.mjs    сквозной тест на синтетических сломанных файлах
```

## Сборка

Требования: Node 22, git. На Mac — Xcode Command Line Tools (`xcode-select --install`).

```bash
npm ci
npm run untrunc      # собирает движок под эту машину → resources/bin/<os>-<arch>/ (5–10 минут)
npm start            # запустить приложение
npm test             # e2e-тест (нужны ffmpeg и ffprobe в PATH)
npm run dist:mac     # .dmg   → release/
npm run dist:win     # .exe   → release/ (собирать на Windows)
```

**Windows**: движок собирается в MSYS2 (терминал «MINGW64»):

```bash
pacman -S --needed git make diffutils mingw-w64-x86_64-gcc mingw-w64-x86_64-nasm
bash scripts/build-untrunc.sh
```

Затем в обычном терминале: `npm ci && npm run dist:win`.

**CI**: `.github/workflows/build.yml` собирает dmg (arm64 и x64) и exe (установщик и portable) по тегу `v*` или вручную, перед этим прогоняет тесты на Linux. Готовые файлы лежат в Artifacts.

## macOS: неподписанное приложение

Сборка не подписана сертификатом Apple. При первом запуске:

```bash
xattr -cr "/Applications/Video Rescue.app"
# если пишет «повреждено» на Apple Silicon:
codesign --force --deep -s - "/Applications/Video Rescue.app"
```

## Советы операторам

- Эталон: снять 30–60 секунд **той же камерой** без смены настроек (разрешение, fps, кодек/битрейт, звук, прокси).
- Если восстановилось только начало, включите в разделе «Дополнительно» пропуск нераспознанных участков (режим «Новый файл»).
- Не форматируйте карту, пока видео не восстановлено. У многих камер есть своя функция восстановления (у Sony это «Восстановить БД изображений»): попробуйте сначала её, вставив карту обратно с заряженной батареей.
